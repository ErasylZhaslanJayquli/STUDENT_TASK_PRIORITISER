# Student Task Prioritizer

Небольшой сервис для студента: по четырём признакам задания модель машинного обучения определяет приоритет (`High` / `Medium` / `Low`), а приложение на Streamlit показывает и сортирует список заданий.

Курс ICT1103 · второй рубежный контроль (топтық жоба) · команда: Jujutsu kaisen

## 1. Проблема, пользователь, результат

- **Проблема.** При нескольких дедлайнах трудно решить, за какое задание браться первым.
- **Пользователь.** Студент бакалавриата, у которого несколько предметов одновременно.
- **Результат.** Приложение принимает задание (срок, сложность, время, важность) и показывает приоритет, предсказанный моделью.
- **Как проверяем.** Точность модели на отложенной test-части выше базового уровня «всегда Low» (0,40); приложение использует именно эту модель, а не готовую формулу.
- **Связь с курсом.** Неделя 6 «Оқытушымен оқыту»: классификация табличных данных (ПОН 5).

## 2. Данные

- Файл `student_task_prioritizer_dataset.csv`: 100 строк, без пропусков.
- Признаки: `difficulty` (1–5), `days_left` (0–14), `estimated_hours` (1–8), `importance` (1–5). Целевая переменная: `priority`. Дополнительные колонки `subject`, `task_type` в модель не входят (проверка показала, что качество не растёт).
- Классы: Low 41, Medium 38, High 21.
- **Данные синтетические**, созданные командой для учебного проекта. Реальных людей и персональных данных нет.
- **Происхождение данных и условия использования.** Датасет `student_task_prioritizer_dataset.csv` был создан участником команды с помощью генеративного искусственного интеллекта для учебного проекта Student Task Prioritizer. ИИ использовался для генерации 100 синтетических примеров учебных заданий с различными характеристиками: сложностью, сроком выполнения, предполагаемой продолжительностью и важностью. Датасет не содержит реальных персональных данных и используется исключительно в образовательных целях. Данные созданы для данного проекта, поэтому лицензия стороннего датасета не требуется.
- **Формирование целевой переменной `priority`.** Каждому заданию при генерации была присвоена одна из трёх меток: `High` (высокий приоритет), `Medium` (средний) или `Low` (низкий). Эти метки используются как целевые значения при обучении модели классификации. Предполагаемые факторы приоритета — количество дней до дедлайна, важность, сложность и время выполнения. Точная формула или инструкция, по которой ИИ назначал метки, не сохранилась, поэтому согласованность разметки не гарантируется. В дальнейшем качество модели оценивается путём сравнения её предсказаний с метками исходного датасета.
- Обработка (`ml_model.load_data`): проверка колонок и пропусков, затем деление 80/20 со стратификацией, `random_state=42`.

## 3. Как это работает

```
задание (срок, сложность, часы, важность)
   → days_left = max(срок − сегодня, 0)
   → Decision Tree (ml_model.predict_priority)
   → приоритет + уверенность модели
   → сортировка и показ в интерфейсе
```

**Метод:** решающее дерево (`max_depth=3`, `min_samples_leaf=3`, подобраны 5-fold CV только на train). Дерево даёт читаемые правила (`ml_outputs/tree_rules.txt`) и не требует масштабирования признаков.

| Метод (повторная CV 5×10 на train) | Accuracy |
|---|---|
| Decision Tree (выбран) | 0,612 ± 0,088 |
| Logistic Regression | 0,818 ± 0,088 |
| k-NN (k=5) | 0,655 ± 0,086 |
| Random Forest | 0,668 ± 0,087 |

Логистическая регрессия точнее, но дерево выбрано ради интерпретируемости: правила можно показать пользователю и объяснить на защите.

## 5. Запуск

```bash
pip install -r requirements.txt
streamlit run app.py            # приложение
python ml_model.py              # (по желанию) переобучить модель и пересчитать метрики
python -m unittest -v           # тесты
```

Модель и тесты проверены на Python 3.12, scikit-learn 1.9.1, pandas 3.0.6, matplotlib 3.11.2, joblib 1.6.0. Если `model.joblib` не открывается (другая версия scikit-learn), модель переобучается автоматически. GPU и платные сервисы не нужны.

**Как пользоваться.** В «My Tasks» или «Quick Add» введите название, срок, время, сложность и важность. Колонка «ML Priority» покажет предсказание дерева. Задания можно удалять, сортировать, а список скачать в `tasks.csv` и загрузить обратно (во вкладке «Save / load tasks»).

## 6. Результаты проверки

Test-часть (20 строк) использована один раз, после подбора параметров на train.

| Метрика | Значение |
|---|---|
| Accuracy на test | 0,70 (14 из 20); базовый уровень 0,40 |
| Macro F1 на test | 0,673 |
| Accuracy, повторная CV на train | 0,612 ± 0,088 |

Матрица ошибок (строки: истина, столбцы: прогноз):

| | High | Medium | Low |
|---|---|---|---|
| **High** | 2 | 2 | 0 |
| **Medium** | 1 | 5 | 2 |
| **Low** | 0 | 1 | 7 |

Три примера проверки (из test-части, `ml_outputs/validation_examples.csv`):

| Задание | difficulty | days_left | hours | importance | Истина | Прогноз |
|---|---|---|---|---|---|---|
| T073 | 3 | 1 | 5 | 5 | High | High |
| T078 | 1 | 14 | 2 | 3 | Low | Low |
| T017 | 4 | 2 | 7 | 1 | Medium | Medium |

**Разбор ошибки.** T058 (`difficulty=5`, `days_left=3`, `hours=8`, `importance=5`): истинный приоритет High, модель дала Medium. Все задания с `days_left` от 2 до 6 идут в ветку «`difficulty` > 2,5 → Medium», где важность не проверяется. Тот же эффект виден в приложении: «Group project slides» (сложность 5, важность 5, срок 6 дней) получает Medium.

**Тесты:** 27 тестов (`python -m unittest -v`) проходят: данные и диапазоны, три примера проверки, неверный ввод, размеры train/test, сравнение с базовым уровнем, добавление/удаление/сортировка/сохранение заданий, цепочка «задание → модель → приоритет».

## 7. Ограничения

1. Данных мало (100 строк, в test 20): одна строка весит 5 п.п., поэтому 0,70 ненадёжно, реалистичная точность около 60–70 %.
2. Данные синтетические: модель выучила закономерность набора, а не поведение реальных студентов.
3. Дерево глубиной 3 использует не все признаки; в `tree_rules.txt` есть разбиения с одинаковым классом на обеих сторонах.
4. Классы упорядочены (Low < Medium < High), но дерево этого не учитывает: ошибка на один и на два уровня для него равны.
5. Приложение хранит задания в сессии браузера; сохранение выполняется вручную через CSV.
